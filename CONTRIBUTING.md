# Contributing to Local Mind

Thanks for considering a contribution!

## Before you start

1. Read the README and explore the existing project structure.
2. Check existing issues to avoid duplicating work.
3. For large changes, open an issue or discussion first.
4. Keep changes focused and describe the user problem they solve.

## Development guidelines

- Follow the conventions already used in the codebase.
- Keep the interface responsive and accessible.
- Include helpful loading, empty, and error states for user-facing flows.
- Never commit API keys, access tokens, passwords, or private user data.
- Update documentation when setup steps, configuration, or behavior changes.
- Add or update tests when the repository has a test setup.

## Pull request checklist

- [ ] The purpose and behavior of the change are explained.
- [ ] Existing project conventions are followed.
- [ ] Tests, lint, or build checks were run where available.
- [ ] Screenshots are attached for meaningful UI changes.
- [ ] Documentation is updated.
- [ ] No secrets or personal data are included.
